# Wr840n v4 cams v7.6 (OpenWrt 24.10, mjpg-streamer)

Робоча v7.4 на OpenWrt 24.10 без ustreamer і без USB/IP, з вбудованим luci-app-usbdiag 1.0-r3.

## Що змінено відносно v7.4
- **ustreamer прибрано** (пакет, вибір рушія, вкладка «Рушій», налаштування якості тощо). Усі камери працюють через mjpg-streamer (`http://роутер:порт/?action=stream`).
- **USB/IP прибрано** повністю: пакети, `cams-usbip`, hotplug, пункт меню, режим у службі.
- **luci-app-usbdiag 1.0-r3** (Status -> USB Diagnostics) вкладено у `files/`. З нього прибрано «час роботи» (він є на головній сторінці); у підказці до часу події лишився час від старту ядра.
- **Патчі 040, 050, 060 без змін** (як у робочій v7.4: швидкий YUYV->JPEG через `raw_data_in`, який на libjpeg-turbo 24.10 працює правильно). Кольорові смуги були лише на libjpeg 9c у 19.07, там патчі інші.
- Меню (Services): «Вебкамери», «Вебкамери: трафік» (вмикається прапорцем у «Загальне»), «Вебкамери: параметри камер».
- Сторінка трафіку: кадри на кожному кроці були лише для ustreamer, тепер показуються байти (nft-лічильники) і кількість глядачів.

## Збірка
Actions -> Run workflow, `openwrt_ref` = `openwrt-24.10`, `lan_ip` = 192.168.77.10. Артефакти: sysupgrade.bin, SHA256SUMS, config.used. Лог кінця показує розмір образу відносно 7808 КБ.

## Не перевірено
Збірка в Actions, JS-сторінки на роутері.

## Сумісність патчів з 24.10
Фід 24.10 збирає mjpg-streamer **v1.0.0** (у 19.07 був коміт 2018-10-25). Перевірено: на чистому v1.0.0 лягають по черзі фідові 010-030 і наші 040, 050, 060 (без fuzz і зсувів); jpeg_utils.c компілюється з libjpeg-turbo, тест кадру 320x240 з поворотом і без: Y 0.5, Cb/Cr ~0.9.
